# Contributing to AI Weather Market App

Thank you for your interest in contributing to the AI Weather Market App! This document outlines the best practices and guidelines to help you contribute effectively and collaborate smoothly with the project maintainers and community.

---

## Introduction

We welcome contributions of all kinds, including bug reports, feature requests, documentation improvements, and code enhancements. By contributing, you help improve the project and make it better for everyone.

---

## How to Contribute

### Reporting Issues

- Search existing issues to avoid duplicates.
- Provide a clear and descriptive title.
- Include detailed steps to reproduce the issue.
- Attach relevant logs, screenshots, or error messages.

### Feature Requests

- Clearly describe the feature and its benefits.
- Provide examples or use cases if possible.
- Be open to discussion and feedback.

### General Contributions

- Fork the repository and create your branch from `main`.
- Make your changes in a dedicated branch.
- Write clear, concise commit messages.
- Ensure your code follows the project's coding standards.

---

## Branching and Pull Request Guidelines

- Use descriptive branch names (e.g., `feature/add-weather-api`, `bugfix/fix-db-connection`).
- Keep your branches focused on a single purpose.
- Before submitting a pull request (PR), update your branch with the latest changes from `main`.
- Include a detailed description of your changes in the PR.
- Link related issues or feature requests in the PR description.
- Be responsive to review comments and make necessary updates promptly.

---

## Coding Standards

- Follow PEP 8 for Python code style.
- Use meaningful variable and function names.
- Write modular, reusable, and well-documented code.
- Include comments where necessary to explain complex logic.
- Format code consistently using tools like `black` or `flake8` if applicable.

---

## Testing

- Write tests for new features or bug fixes.
- Run existing tests to ensure nothing is broken.
- Use the provided test framework and follow existing test patterns.
- Include instructions for running tests if they differ from standard commands.

---

## Communication

- Use GitHub issues and pull requests for discussions related to the project.
- Be respectful and constructive in all communications.
- Ask questions and seek help when needed.
- Engage with the community in a positive and collaborative manner.

---

## Code of Conduct

We expect all contributors to adhere to the [Code of Conduct](CODE_OF_CONDUCT.md) to maintain a welcoming and inclusive environment. Please read it before contributing.
